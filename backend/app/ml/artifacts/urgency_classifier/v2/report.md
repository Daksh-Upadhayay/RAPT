# Urgency classifier v2

Weak supervision: keyword/heuristic rules (`app/ml/weak_labels.py`) label the training
data, then TF-IDF word 1-2-grams + tone features (VADER sentiment, caps ratio, `!`/`?`
counts, length) feed a classifier trained on those labels, with class-balanced weights.
XGBoost and logistic regression are both trained, and the one with the better val
macro-F1 is shipped: **LogReg**.
Generated by `scripts/train_urgency_model.py`; numbers are in `metrics.json`.
Dataset: `urgency_tickets.csv`.

Weak label distribution (train, 7163 rows):
low 3613 (50%), medium 2361 (33%), high 1189 (17%).

## Summary

| model | val (weak) macro-F1 / acc | test (weak) macro-F1 / acc | handwritten (human) macro-F1 / acc |
|---|---|---|---|
| XGBoost | 0.82 / 0.82 | 0.82 / 0.84 | 0.45 / 0.49 |
| LogReg | 0.88 / 0.89 | 0.80 / 0.81 | 0.63 / 0.62 |

**Rules alone on the hand-written set:** macro-F1 0.68 / accuracy 0.67.

- **val / test (weak)**: agreement with the rules' labels on held-out data. This measures how
  well the model *learned the rules*, not how well it predicts real urgency.
- **handwritten (human)**: agreement with urgency labels a person assigned. Compare it
  with "rules alone": the model earns its place only if it does at least as well as the
  rules it was trained on. Caveat: v1's errors on this set were studied while
  redesigning the v2 training data, so from v2 on it is no longer a clean test. The
  clean check is a fresh set scored with `scripts/evaluate_model.py` (DECISIONS.md, Phase 2).

## Labeling functions

together with a MEDIUM rule; MEDIUM if one weak HIGH or any MEDIUM rule fires; otherwise LOW.
